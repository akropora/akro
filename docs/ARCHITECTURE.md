# Akro V2 Architecture

## Request path

```text
terminal input
    -> core commands
    -> explicit slash skills
    -> project instructions
    -> global + project memory retrieval
    -> global + project knowledge retrieval
    -> bounded recent chat history
    -> Ollama main model
    -> streamed response
    -> chat autosave
    -> tiny-model memory refresh
```

## Core and data are separate

The repository contains code and bundled skills.

User data lives under `~/.akro` by default.

```text
~/.akro/
  state.json
  runtime/
  global/
    brain/
    knowledge/
  projects/
    default/
      project.json
      chats/
      documents/
      brain/
      knowledge/
```

## Memory retrieval

Brain notes are generated by Librarian and store a compact summary plus a small set of fields:

```text
title
summary
importance
memory_type
user_context
key_points
decisions
open_items
keywords
```

`memory_type` stays deliberately small:

```text
fact
preference
project
decision
goal
temporary
```

Retrieval combines:

1. keyword overlap
2. optional semantic similarity
3. Librarian importance
4. a small recency bonus

Only the highest-scoring notes are inserted into the main model prompt.

## Knowledge retrieval

Imported plain-text documents are stored as raw documents and exact chunks.

The raw source remains authoritative.

Knowledge retrieval scores chunks against the current request and inserts only a few exact source chunks into the main model prompt.

This keeps document facts separate from generated memory summaries.

## Embeddings

Semantic retrieval is optional.

If `AKRO_EMBED_MODEL` is installed in Ollama, Akro stores embeddings for Brain notes and document chunks. If the model is unavailable, Akro automatically falls back to lexical retrieval.

This means semantic search improves Akro, but it is not a hard dependency.

## Skills

Core knows how to discover and execute skills, but it does not know what individual skills do.

A skill folder supplies its own manifest and, for tool skills, its own executable.

That is the main V2 extension boundary.

## Projects

Project data is isolated by default.

Global Brain memory is retrieved alongside project memory. Project notes can be promoted to global memory from `/memory`.

The main model does not need a special project-aware model. Akro assembles the right context before calling whatever model is selected.

## V2.1 prompt refinement

`/promptup` is a tool skill. It receives the current transformed request, retrieves at most a tiny amount of relevant memory, and asks `coral1.6-prompt` to rewrite the request. The improved request then continues through the remaining skill pipeline and finally reaches the selected main model.

## Background remembering

Normal chat turns no longer block on Librarian. After a response is saved, Akro snapshots only the newest user/assistant pair into a small job file. `lib/remember-worker.sh` processes jobs serially in the background with a smaller Librarian context and generation budget. Brain index writes use a simple lock plus atomic file replacement.

Full `/learn` and `/learn-all` remain available for deliberate project-wide learning.

## Sandbox

The `sandbox` project is created automatically and is marked isolated. It does not retrieve global or project Brain memory, does not retrieve persistent knowledge, and never queues chat turns for remembering. `/document` in Sandbox is temporary and inline-only for small text files.
